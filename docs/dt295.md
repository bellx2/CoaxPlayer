# PIX-DT295

ピクセラの PIX-DT295 は coax が対応していないので、[pix-userland](https://github.com/Khronos31/pix-userland) の `pixd` と `pix-ts` で受信し、その TS を coax に通して再生する。`pixd` と `pix-ts` は `.app` に同梱している（選局を速くした fork、[bellx2/pix-userland](https://github.com/bellx2/pix-userland) の `main` でビルドしたもの）。

```
pixd（DT295 を受け持つ）
pix-ts -c T27 -t - -o - ──▶ coax tune --input - --stats --program ──▶ 中継（字幕・録画）──▶ mpv
```

## 用意するもの

- DT295 のファームウェア `dt295.bin`。pix-userland のリポジトリや配布アーカイブの `firmware/dt295.bin` にある

ファームウェアはこのアプリに含まれない。`dt295.bin` はメーカー由来のデータを含み、再配布が制限されているためである。

## 設定

設定画面（⌘,）の「チューナー」で「PIX-DT295（pix-userland）」を選び、「dt295.bin を選ぶ…」でファームウェアを指定する。どちらも次の起動でも使う。

`.app` に同梱した `pixd` と `pix-ts` を使う。開発中（`swift run`）は同梱が無いので、配布アーカイブの並びとみなし、`<フォルダー>/firmware/dt295.bin` の `<フォルダー>` にある `pixd` と `pix-ts` を使う。

## 動き

- チューナーを PIX-DT295 にすると、`pixd --list-json` で DT295 の USB の位置（`3-1.1` など）を調べ、`pixd --device usb:<位置> --firmware <dt295.bin> --instance coaxplayer --runtime-dir $TMPDIR/CoaxPlayer-pix` を起動する。`pixd ready` の行が出たら選局できる。それより前に選んだ局は、準備ができてから選局する
- `pixd` を受け持つ間は `$TMPDIR/CoaxPlayer-pix.lock` に flock をかけておく。CoaxPlayer を 2 つ起動したときは、あとのものはロックを取れないので `pixd` に触らず、デバイスの状態に「ほかの CoaxPlayer が PIX-DT295 を使っています」と出す。先のものを終了してから「デバイスを再スキャン」を押すと使える
- flock は持ち主が落ちると外れる。ロックを取れたのに `pixd` が動いていれば、落ちた CoaxPlayer の残りなので、止めきってから（最大 3 秒待ち、終わらなければ SIGKILL）起動し直す
- 選局すると `pix-ts --receiver 0 -c T<物理チャンネル> -t - -o -` を起動し、その出力を `coax tune --input - --stats --program` の stdin につなぐ。coax の stderr の行（番組と受信状態）は、coax のチューナーで受信したときと同じように使う
- DT295 の TS はスクランブルが解けているので、外部デコーダーも `coax pcsc` も使わず、フルセグを再生する
- 止めるときは `pix-ts` を先に止める。`coax tune --input` は入力が終わると自分で終わる
- 一覧の今の番組は集めるが、プレビューは集めない。1 局の選局に 2〜3 秒かかり、プレビューまで待つと一覧がそろうのが遅れるため
- 映像が出ないときに選び直す見張りは、選局したときではなく、最初の受信状態の行が届いたとき（TS が流れ始めたとき）から 5 秒で数える。`coax tune --input` はデータが届くまで受信状態の行を出さないので、選局にかかる時間が pix-userland の版で違っても同じように働く
- 番組集めの時間切れは、上流の pix-userland でも間に合うよう 15 秒にしている（coax のチューナーでは 10 秒）
- アプリを終了するときに `pixd` を止める

## スキャン

設定画面の「チャンネルスキャン」も PIX-DT295 で行う。coax の `scan --tune-command` に pix-ts のコマンド（`-c T{ch}`）を渡し、coax がチャンネルごとに `{ch}` を物理チャンネルに置き換えて pix-ts を起動する。

```
coax scan --discover=ISDBT --lock-timeout 3s --include '^(選んだ範囲)$' --output <scan.json> --data-timeout 5s \
  --tune-command "'<pix-ts>' '--runtime-dir' '...' '--instance' 'coaxplayer' '--receiver' '0' '-c' 'T{ch}' '-t' '-' '-o' '-'"
```

- pix-ts からはロックが分からないので、5 秒（`--data-timeout`）の間に TS が届かないチャンネルを受信できないとみなす。受信できないチャンネル 1 つに約 5 秒かかる（東京で 20〜29ch と 40ch の 11 チャンネルを調べて 48 秒）
- 受けるのは地上 UHF だけで、ケーブルの範囲を選んでも何も見つからない
- 上流の pix-userland は流れ始めるまでに約 9 秒かかり、5 秒では見つけられない（同梱しているのは速くした fork）
- 中止すると coax が pix-ts を止める。次のスキャンは続きから調べる

## 制限

- 選局してから映るまで 2〜3 秒かかる（上流の pix-userland では約 9 秒）。pix-ts が PSI（PAT・PMT・CAT）を集めて PID の割り当てを決めてから流し始めるためである
- 地上波（13〜62ch）だけを受ける。ケーブルと衛星は受けない
- 受信状態の行には、ロック、CNR、信号の強さ、ドロップ数が出ない（coax は入力の TS しか見ないため）
- macOS では、差し込み口によって DT295 の USB の位置を読めず、`pixd` が DT295 を選べないことがある。デバイスの状態に「USB の位置を読めません」と出たら、別の差し込み口に挿し直す
